# BingX Short Bot

Асинхронный Telegram-бот на Python 3.11, который читает только публичные рыночные данные BingX perpetual swaps через `ccxt.async_support` и отправляет сигналы на потенциальный шорт. Ордеров и запросов к приватному API нет.

Binance намеренно не используется.

## Логика сигнала

Все расчёты выполняются только по завершённым свечам выбранного `TIMEFRAME` (по умолчанию 15m). Одновременно должны выполняться условия:

- рост хотя бы в одном окне: 1h ≥ 10%, 4h ≥ 20% или 24h ≥ 30%;
- 24h quote volume ≥ 3 000 000 USDT;
- RSI(14) выбранного таймфрейма ≥ 75 либо рост в любом окне ≥ 50%;
- текущая цена на 5–10% ниже максимума последних 24 часов;
- максимальное отношение объёма одной из свечей за последние 2 часа к предшествующей rolling-20 базе ≥ 1.3;
- close последней свечи не выше предыдущего close;
- объём последних трёх свечей / объём предыдущих трёх ≤ 1.3.

Сигнальная цена — последний завершённый close. Зона набора строится как
сигнальная цена ± `ENTRY_ZONE_PCT` (по умолчанию 3%). Цели считаются от
центра зоны: −5.5%, −10%, −15%; стоп расположен на
`SL_ABOVE_ZONE_PCT` (по умолчанию 8%) выше верхней границы зоны. Повторный
сигнал не отправляется, пока активный не закрыт по SL или TP3 либо не истекли
`SIGNAL_VALID_HOURS` (по умолчанию 6 часов). Если одна свеча касается обоих
уровней, первым считается SL. Зона 2 намеренно не рассчитывается, поскольку
её исходная формула не подтверждена.

После достижения каждой цели бот отправляет отдельное уведомление о TP1, TP2
или TP3. Если цена достигает SL, бот отправляет уведомление о стоп-лоссе.
Уровни контролируются по high/low завершённых свечей и дополнительно по
текущей ticker-цене BingX при каждом проходе сканера.
Каждое уведомление содержит ID исходного сигнала и отправляется в Telegram
ответом на исходное сообщение. Если исходное сообщение удалить, уведомление
будет отправлено отдельно, но ID сигнала останется в тексте. TP1 и TP2 не
закрывают сигнал: он остаётся активным до TP3, SL или окончания срока.
Неотправленные события сохраняются в `STATE_FILE` и повторяются после
временной ошибки Telegram.

## Локальный запуск

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполните BOT_TOKEN, TELEGRAM_CHAT_ID и при необходимости ADMIN_IDS
python check_api.py
python main.py
```

Команды Telegram:

- `/start` — запуск и список команд;
- `/status` — состояние автоматического сканера;
- `/settings` — текущие параметры стратегии;
- `/help` — справка по ручному анализу;
- `/analyze BTC` — подробный анализ любой активной USDT-M монеты BingX;
- `/scan BTC` — короткий псевдоним `/analyze`.

Для ручного анализа принимаются форматы `BTC`, `BTCUSDT` и
`BTC/USDT:USDT`. Команда не обязательна: можно просто отправить тикер
обычным сообщением, например `FLOCK`. Результат содержит динамику за
1h/4h/24h, RSI, оборот,
пик и откат, объёмные коэффициенты, состояние каждого критерия и уровни
входа/TP/SL, если SHORT-сигнал подтверждён. Ручной анализ использует
публичные данные BingX и не требует API-ключей. Для быстрой навигации разделы,
пройденные и непройденные критерии, итог и торговые уровни отмечаются
смысловыми эмодзи. Healthcheck: `GET /health`.

Бот приватный. По умолчанию доступ разрешён Telegram ID `401028479`.
Переменная `ADMIN_IDS` принимает один или несколько числовых ID через запятую,
например `401028479,987654321`. Ограничение применяется ко всем входящим
сообщениям, включая команды и тикеры без команды. Неавторизованный пользователь
получает ответ `❌ Извините, этот бот приватный.`

`/status` показывает общее число обнаруженных рынков, прогресс текущего цикла и длительность последнего полного сканирования. INFO-логи направляются в stdout, поэтому Railway не должен ошибочно помечать штатные строки запуска как `error`.

BingX иногда оставляет в каталоге рынок, у которого endpoint свечей возвращает код `109415` (`is pause currently`). В пределах текущего цикла такой рынок попадает во временный runtime blacklist. Перед каждым следующим циклом blacklist очищается, все ранее paused-рынки проверяются снова, восстановившиеся автоматически возвращаются в обычное сканирование, а всё ещё остановленные формируют обновлённый список.

После каждого полного цикла бот также выполняет `load_markets(reload=True)`. Новые активные USDT-M swaps добавляются без перезапуска, а снятые с торгов рынки удаляются из следующего прохода.

`SYMBOLS=ALL`, `SYMBOLS=*`, пустая переменная или полное отсутствие переменной включают полный рынок. В этом режиме бот через `load_markets()` автоматически обнаруживает и последовательно сканирует все активные BingX USDT-M perpetual swaps без whitelist и без ограничения по числу токенов. Чтобы добровольно ограничить охват, можно передать unified symbols через запятую, например `BTC/USDT:USDT,ETH/USDT:USDT`; регистр автоматически нормализуется, а недоступные рынки пропускаются с предупреждением. `TIMEFRAME` настраивается без изменения логики; допустимы интервалы не больше 1h, которые делят час без остатка.

`ACCOUNT_SIZE=0` скрывает размер позиции. При положительном размере риск в
USDT равен `ACCOUNT_SIZE × RISK_PCT / 100`. Размер рассчитывается
консервативно по максимальному расстоянию от нижней границы Зоны 1 до SL,
чтобы риск не был превышен при заполнении в любой точке зоны. Требуемая
маржа равна `notional / LEVERAGE`.

`BINGX_API_KEY` и `BINGX_SECRET` оставьте пустыми: текущая версия использует только публичные candles/ticker и не передаёт ключи в ccxt.

## Railway

1. Создайте новый Railway Project и подключите репозиторий с этой директорией.
2. Railway автоматически использует `Dockerfile` и `railway.json`.
3. В Variables добавьте `BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ADMIN_IDS=401028479` и нужные параметры из `.env.example`.
4. Добавьте persistent Volume и смонтируйте его, например, в `/data`; установите `STATE_FILE=/data/signals_state.json`.
5. Railway задаёт `PORT` автоматически. Сервис должен иметь публичный domain, чтобы Railway мог вызвать `GET /health`.
6. Для smoke-проверки всего market discovery откройте Railway Shell и выполните `python check_api.py`. Ожидается строка `OK: BingX public API...` с полным числом найденных swap markets. Для одного быстрого контрольного запроса можно выполнить `SYMBOLS=BTC/USDT:USDT python check_api.py`.
7. Для сравнения доступности BingX, Binance Futures и WEEX из реального
   исходящего IP контейнера выполните `python check_exchanges.py`. Скрипт не
   требует API-ключей, показывает количество рынков, проверяет свечи и тикер,
   а для Binance отдельно распознаёт HTTP 451 `restricted location`.

Это веб-сервис с фоновым scanner task, а не отдельный worker: один процесс одновременно держит HTTP healthcheck и long polling Telegram. Не масштабируйте сервис больше чем до одной реплики, иначе несколько poller-процессов будут конкурировать.

Подробный разбор провайдеров и результаты тестов находятся в
`API_PROVIDER_INVESTIGATION.md`.

## Тесты

```bash
pytest -q
```

Тесты не обращаются к сети: стратегия получает искусственные DataFrame, жизненный цикл сигналов использует временный JSON-файл.
